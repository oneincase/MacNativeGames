# 第一章节「人物模型黑」排查记录（2026-10-23）

用户实机反馈（原话）：「我实测了多个存档，不是伽马问题，人物模型都是黑色的，感觉是贴图的问题」。
截图 = 暗底 + 金色环形 + 蓝光点 + 小地图 + 「可保存」；`FPS 30 2990x1674`、`新着色器 23 / 总计 293`。
量化：用户图整体亮度 19.1–21.0，对照飞行场景正常帧 96.8（`/tmp/pngdark.py`）。

## 已排除

| 假说 | 证伪方式 | 结论 |
|---|---|---|
| 伽马/曝光 | 上屏加 `NIER_GAMMA`（0.6）后亮度几乎不变（22.3 vs 21.0），且用户明说不是伽马 | 排除 |
| GS 未翻译导致几何缺失 | GS（`137b54dc`）经 `totk_xlate` 批处理成功产出 SPIR-V，GLSL 反查显示 `layout(passthrough)`、无 `EmitVertex`/`EndPrimitive`，顶点位置完全直通；缺失只会多画 `gl_ViewportMask=0` 那批 | **GS 不是根因**（详见 `gs-finding-2026-10-23.md`） |
| 贴图格式猜错 | 模型贴图 `nvnfmt=0x8b` → `0x79..0x94` 区间 → `ASTC_SRGB0(186)+astc_off[4]` = **190 = ASTC 6x6 sRGB**；`fmt_of` 给 `{16,6,6}`，块大小与映射都对 | 排除 |
| 贴图上传整体失败 | `DM_NVN_TEXPNG_FS=ba879d1a` 抓到 27 张绑定纹理，其中 `ser=147500` 解出完整的「NieR:Automata」logo 文字（1024x64），说明 CPU 上传/ASTC 解码链路能出正确内容 | 排除「上传全坏」 |
| 两个疑似空壳 FS 写主画面 | `49bd7a78` 的 MSL 只有 32 行、输出全 0；改成 0.55 灰后画面亮度 23.5 → 24 不变。`3b3b433a` 有正常颜色计算（`fma` 链），改成纯红后亮度 21.8 不变 | 两者都**不写 ser=16 主画面** |

## 新发现的确定性回归（与人物黑独立）

`NIER_GS_COMPACT=1` 读档后**帧 3300 必崩**（c259/c260/c261/c262/c263 五批全中）：

```

[tex] 拷贝按 Metal 上限截断 ser=1645 声明 4608 层 实用 2046 层
【红】上传命令缓冲执行出错 … Code=2 Caused GPU Address Fault Error (0x0b: PageFault)
上传命令缓冲被丢：这一批 10326 张贴图记为内容未写，下次取用时重传
【红】分段命令缓冲错误 fence=2606 … InnocentVictim
```

- 与 gamma、bloom clamp（`NIER_KEEP_BLOOM_INF=1`）都无关（c261/c262 分别关掉后照崩）。
- `NIER_GS_COMPACT=0`（launcher 现用路径）**不崩**（c264：帧 4500、0 崩）。
- 08:37 的 c248 同脚本不崩 → **新二进制回归**，嫌疑集中在 GS 压缩路径 + 读档时的 cube array 上传批次。

## 阻塞：自动脚本进不到用户说的场景

读档后无论「确认」×6 + 「前进」×8（c265）、「前进」×40（c272，帧 8100）、还是「前进+射击」混合，画面始终是降落黑场（亮度 21–28），没有出现用户图中的花草/城市废墟。
→ 说明该场景需要用户自己的操作序列（或更长的过场推进），盲按键不可靠。
