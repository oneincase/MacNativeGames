# 3D 场景绿色调偏色：诊断（2026-10-22，白屏解除后转入）

用户实机对照确认：序章飞行场景原版为**中性灰白天空 + 橙色引擎光**，移植为**深绿海面 + 品红引擎光**。本文记录本轮排查到的边界与下一步。

## 量化签名（Pillow 通道统计，最亮 5% = 中性色检验）

| 画面 | 路径 | 最亮 5% | 判定 |
|---|---|---|---|
| 标题 / logo 影片 | 解码→贴图→screen（不经 3D 光照） | R237 G234 B226 | **中性 ✓** |
| 序章飞行场景 | 世界 HDR RT ser=16（泛光/tonemap **之前**） | R69 G184 B72 | 偏绿 ✗，G/R=2.67 G/B=2.56 |
| 引擎光（同帧放大） | 同上 | 品红=814 橙=50 | 橙→品红 ✗ |

**关键**：偏色在**世界几何 pass 直接写出的 HDR 缓冲**里就已存在，早于一切移植后处理捷径（泛光 `DM_NVN_BLOOM_Q`、tonemap、换格式合成）——所以不是后处理引入。

## 已排除（每条都有实测，勿重走）

1. **通道交换（G↔B / R↔B）**：反证——中性灰白 (230,230,230) 若纯通道交换应保持三通道相等，但实测变 (69,184,72) 三通道不等。**是逐通道增益错误，不是置换。**
2. **NVN 纹理 swizzle**：c172（`DM_NVN_TEXPNG_FS` 读出 tonemap 系采样的全部 HDR RT）——ser=16/24/25/26/82/83/84/89 的 `swz` 全是 `2,3,4,5`（R,G,B,A 恒等），`nvnfmt=0x3f`（R11G11B10F）→ Metal 92 精确映射。游戏没声明重排，我们没丢。
3. **mip 采到低层**：c162 `NIER_FORCE_LOD0=1` 与基线标题逐通道不变（236,234,226 vs 237,234,226）。
4. **静态贴图数据错**：c168 世界 shader 采样的烟雾图（中性灰）、法线图（蓝 (127,127,243)，若被采样期交换应显绿——没有）、mask 图全部正常。
5. **RT 位域错位**：ser=16 是 GPU 写 GPU 读的同一 Metal 纹理对象，位域解释对读写天然自洽，不可能错位。
6. **顶点色属性被错读**：VS `2fec68ad` 的输出 varying `m_44 = (_674,_732,_674,_732)` 是 shader 自身的通道复制（x==z、y==w），不是属性错位；且无任何 shader 读 support_buffer 的 `is_bgra`（全库扫描 0 命中）。

## 剩下的两条具体线索（下一轮从这里做）

### 线索 A：驱动常量空洞 `c2+0x160`（历史标记"画面未验证"，从未跟进）
全库扫描只有 **2 个片元程序**读不填区 `c2+0x160`：`31d321589226`（`as_type<int>`）、`57290de615ee`（float，c165 世界帧里 4 笔）。`drv_fillable(bank=2)` 的空洞是 `[0x120,0x168)`，`0x160` 恰在边界（紧邻 0x168 的贴图句柄表）。`57290de6` 把它当逐通道 tint 的一个分支值用（`_105` 为真时 `_107=c2+0x160.z`，否则用贴图采样）。**读到 0 可能让某通道增益归零。**
- 判据实验：给 `runtime_watch_tick` 或 `draw_inner` 加一次性日志，打世界帧里这两个程序**实际读到的 `c2+0x160` 值**与 `_105` 分支走向；若 `_105` 常真且 `_107` 参与输出 → 需要给该位置填真值（真值来源：Switch 上 NVN 驱动在此处放什么，需抓真机或从 `nvnGetDriverUniformLocation` 语义推）。

### 线索 B：延迟光照的 G-buffer 法线缓冲通道序
`out.rgb = 光照 × tint`，光照 = N·L 依赖法线缓冲（ser=24/25/26 之一，`fmt=92` 1920x1080）。若法线缓冲的写入/采样通道序不一致，漫反射会**逐通道**错，方向可随场景法线分布变化（飞行海面偏绿、城市偏粉紫可统一解释）。
- 判据实验：c167 里 ser=24/25/26 在 dump 帧是全黑（pass 顺序/时机问题）。改在**世界光照 pass 之后、tonemap 之前**用 `DM_NVN_TEXPNG=<法线 ser>` 抓法线缓冲——正确的切线空间法线应偏蓝紫（Z 朝上 ≈ (0.5,0.5,1)）；若偏绿，法线缓冲通道序就是断点。

## 工具性教训（本轮踩的坑）
- `DM_NVN_TEXRAW` 逐张 `cb_wait` 同步读回会**阻塞提交线程 → 驻留积压**，在飞行场景装载突发窗口内 10.9/13.9 GB 两次撞预算闸（c170/c173）。RT 判决改用 `DM_NVN_TEXPNG(_FS)`（走采样 view、不逐张同步等）或 `DM_NVN_CBDUMP`（随 passdump 存 uniform，c174 成功产出 1343 块）。
- 世界 HDR 偏色**不能**用任何单一现成开关（BLOOM_Q / T2T_CONVERT / GS_COMPACT）复现或消除——它在世界 pass 输出即存在。

## 第二轮排除（c174/c176，2026-10-22 下午）

- **c176（世界 pass 342819 采样的 28 张静态贴图逐张 PNG dump）**：全部不偏绿——G-(R+B)/2 最高的是暖色 LUT（3074-3084，R>G>B，+17 是"暖"不是"绿"），其余中性灰/白/法线蓝。**albedo/mask/LUT 输入侧排除**。
- **c174（世界 pass uniform 全量 dump，1343 块）**：真实世界 VS 是 `6d95d272`（72 笔，非之前误追的 2fec68ad）；逐通道 tint 来自材质表 `vp_s0`（4000 条目×160B，tint 在 +48），实际使用的材质索引（`vp_c4`=st0 reg1 的 int[0]：1,6,23,26,30…）的 tint 全是**暖色**（如 (29.15, 9.87, 3.65)）——**材质 tint 数据正常**。FS `7c7dec85` 声明的 cbuf 槽（reg 7/10/12/13）在 dump 里全部在场——**uniform 绑定齐全**。
- **驱动段"空洞 c2+0x160"是误报**：`drv_scan` 按 16 字节块粗粒度报告 `_m0[22]`（起始 0x160 在洞 [0x120,0x168) 内），但两个 shader 实际只读 `.z` 分量 = 字节 **0x168**，恰是已填的贴图句柄表起点。运行时读到的是真句柄，非 0。线索 A 关闭。
- **ryujinx 对照（vendor/ryujinx）**：`SupportBuffer.cs` 布局与我们逐字段一致；`is_bgra` 交换仅 OpenGL 后端使用（Metal 原生支持 BGRA，恒 0 正确）；`TextureHandle.cs` 的 bindless 句柄打包（texId 低 20 | sampId<<20）与我们 c2 句柄表语义一致。ryujinx 无 NieR 专属色彩修正。
- 剩余候选（收窄到 2 条）：
  1. **pass 342815/342817 的 `57290de6`**：它 load 世界 HDR（ser=16）做全屏叠加，把句柄表字节 `c2[22].z` 当 **float** 用（`float _107 = (*fp_c2)._m0[22].z;` 无 as_type）——真机上 NVN 驱动在该位置放的是什么值未证；若我们放的句柄值（如 0x1000000n）被当 float（≈2.4e-39 或 NaN）参与混合，会污染叠加结果。**判据**：`flag skipfs_57290de6` 单开对比截图。
  2. **blend 状态映射**：世界 pass 的 `b0=0x486021828 cmask=0xffff000f`——若 NVN→Metal blend 因子映射错，半透明叠加（天穹/雾/光晕）会系统性偏色。**判据**：对 342815 的 blend 因子逐位核对 `nvnCommandBufferBindBlendState` 的映射表。

## 需要的东西
线索 A/B 的判决都卡在"没有真值对照"：要么有一份 Switch 真机同帧的参考（渲染目标或截帧），要么把 `c2+0x160` 与法线缓冲通道的**期望语义**从 NVN 驱动文档/真机确认。当前移植侧只能定位到"这两处之一"，无法凭空造真值（违反"不用返回成功掩盖未实现"）。

## 附：GS 涂抹假设也已排除
项目历史把"绿色涂抹/green washes"与几何着色器（GS）误剔除关联（CHANGELOG 2026-10-21）。但 c157_d 飞行场景里世界几何**形状正确**（机体轮廓、海面波纹、弹幕都对），只是**颜色**偏绿——不是多余/退化三角形铺屏。GS 压缩（c174 44401 次）产出的是正确几何，偏色在着色输入，非 GS。
